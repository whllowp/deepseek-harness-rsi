# Agent Note: 双核 RSI 知识库的真实模型端到端 A/B

Status: implemented

[English](2026-11-08-dual-core-rsi-real-model-ab.md) | 中文

## Problem

[长期知识库](2026-11-04-dual-core-rsi-knowledge-base.zh.md)以及此前双核 RSI 的全部行为都只用脚本化蒸馏器和桩 agent 验证过。脚本化蒸馏器从不启动蒸馏子代理，也从不产出模型格式的 JSON；桩 agent 作用域注入了策略所需的每一个服务。因此这一机制的价值，以及守护核在随附 Web 组合上的真实行为，此前都未被测量。

## Decision

`apps/web/tests/rsi-knowledge-ab.e2e.ts` 用真实 DeepSeek 适配器运行随附的 Web 组合：五个相同的工作区任务，每个都通过浏览器输入框在新会话中发出，期间定时守护核在没有任何命令的情况下完成蒸馏、门控、采纳并记录台账。`DSH_RSI_AB_ARM` 选择随附组合，或选择交给蒸馏器空知识库的消融组——后者逐字节复现知识库出现之前的任务提示；`DSH_RSI_AB_PAIRED` 把最新的携带知识的输入分别带与不带知识重新蒸馏，因此两种变体看到相同的两代产物与摘要。除非在 record 模式下指定了组别，该场景会跳过。同一变更修复了这些运行暴露的四个缺陷：

- 摘要与未读活动计数只读取用户核心会话。委派出的子代理会话（包括守护核自己的蒸馏子代理）曾占据默认摘要六个名额中的四个，并把每次提案回灌进下一循环。
- 模型 JSON 解码器会去除首尾空白。技能正文末尾的一个换行曾让四次冒烟尝试中的两次失败。
- 策略应用经由 agent 作用域自身的服务隔离解析技能注册表，对每个 agent 全有或全无且相互隔离。严格的 `ctx.skills` 读取曾在真实 agent 作用域上抛错，导致一次携带技能的采纳让之后所有 agent 的创建都失败，蒸馏子代理也不例外。
- 在提交点之前抛错的循环会恢复循环前的状态，并重新应用仍然有效的策略。此前下一条事件记录曾把只完成一半的指针翻转持久化。

## Alternatives considered

只保留脚本化观测台作为证据：被否决，它触达不到这四个缺陷中的任何一个。不修复缺陷直接对比：被否决，摘要污染会给消融组一份关于自己提案的泄漏记忆，失败的循环也会给两组都加入噪声。通过 `agentPresets.serviceFor` 解析注册表：被否决，agent 作用域自身的 `ctx.get` 已遵循 preset 隔离，无需让策略依赖 preset 注册表。在本次变更中限制蒸馏子代理的文件访问：推迟，因为那是子代理能力层面的改动；测试会记录每个子代理的工具调用，使这一泄漏保持可测量。

## Consequences

四条完整轨迹（每组两条，各五轮）都达到了基准满分：随附组在两次试验中都在第 4 个周期达到，消融组分别在第 2 和第 5 个周期达到，因此在这一样本量下轨迹指标落在模型方差之内。配对回放才是受控对比：每种变体十个样本，召回知识的平均得分 0.78，不召回为 0.80，通过门控的次数为五次对四次，差异落在模型方差之内。召回在蒸馏提示中每条约占 240 个字符，并明显影响理由的写法（"不再重新加入先前被拒绝的改进"），但在这一工作负载上没有提高提案得分。每次试验中达到满分的那次采纳，都来自一个用用户核心的工具读取了工作区之外的基准定义或守护核存储的蒸馏子代理：门控并不独立于生成器，消融组也会经由同样的文件泄漏。演化出的策略确实改变了真实行为：第二个任务没有要求运行 `git status`，仍处于空策略的两次试验都没有运行，已采纳策略中写明它的两次试验里有一次运行了；而在采纳的策略下，每一个不带提醒的探针任务都运行了 `git status` 与 `npm test`。
