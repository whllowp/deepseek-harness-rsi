# Agent Note: 守护调度的双核 RSI：咨询制合入与 git 台账

Status: implemented

[English](2026-10-28-dual-core-rsi-daemon-consult-merge.md) | 中文

## Problem

[双核 RSI 模式](2026-10-22-dual-core-rsi-mode.zh.md)让守护核在人类执行 `/rsi run` 或 `rsi_run` 之前保持空闲，且其互换门在候选超过基准阈值的瞬间就替换活跃策略并归档被替换面，不经过询问。一项请求的设计变更提出了相反的默认：守护核应当作为后台服务按自身调度蒸馏，在用户继续工作的同时修复自身失败与卡死的尝试，并在会话退出时总结本次会话的修复点与改进点；任何策略替换都必须有显式的人类合入决策；每次被接受的替换都要记录到本地 git，使每个变更点可审阅、回滚只需一条命令。

## Decision

守护核现在是服务内部的一个重复定时器（`daemonEnabled`，默认开启，`daemonIntervalMs` 节拍）：只有当存在活跃 agent 且知识截止时间之后有新会话活动时，一次 tick 才启动一个调度循环，因此没有新证据就不消耗 token。每次调度尝试受 `cycleTimeoutMs` 时限约束；超时或失败会记录一条持久事件（种类、详情、尝试次数、恢复动作），并按退避重试至多 `daemonMaxRetries` 次后顺延到下一个间隔，卡死或反复失败的循环不会拖垮守护核。事件就是会话的修复点：退出总结会把它与待合入候选的改进点并列展示。

互换门变成了合入门。超过阈值把候选挂起为指针持有的待合入 id（循环结果 `pending`）；更优的后续候选会替换它，而活跃策略从不会自行改变。当最后一个活跃 agent 被注销时，守护核通过可选的 `ctx.userQuestions` 接缝询问一个"合入还是保留"的问题；没有回答方时提议保持待决，交由 `/rsi merge` 与 `/rsi decline`。决策（`merged`/`declined`）会盖章到产生它的循环记录上。

合入会归档被替换代、在合入副本是更优谱系时从它重新播种守护核，并把采纳的产物集作为一次提交记录到专用本地 git 仓库（`ledgerDir`，默认位于 harness 主目录下），回滚同样记录。台账通过 `subprocess` 接缝运行 `git`；缺少 git 可执行文件或提交失败都不会撤销已结算的互换——归档仍覆盖回滚且缺口会被报告——因为事实源是存储域而非台账。交付形式仍是默认关闭的可选 bundle。

## Consequences

启用 bundle 后会按调度消耗模型 token 而无需手动命令；没有新证据的 tick 零成本跳过，`daemonEnabled: false` 恢复仅手动循环。自本次变更起写入的循环记录携带 `pending` 结果与决策字段；更早的 `promoted` 记录仍可解码，因为存储域新增的都是同一域版本下的可选字段。退出咨询要能在原地得到回答依赖 user-questions 回答方；headless 组合回退到命令，这也是测试驱动的界面。台账目录是 `$DSH_HOME`/`~/.dsh` 下新的持久位置，与任何项目工作树分离。

## Alternatives considered

仅自动互换加退出时报告：被否决，因为它在人类决策之前就替换了策略，而请求明确要求以决策为门。多候选合入队列：被否决，因为蒸馏器每轮基于已知最优谱系改进，单一最优待合入候选加守护谱系以一次决策覆盖同样的空间。只在存储域归档记录决策而不使用 git：被否决，因为请求明确把本地 git 历史作为审阅与回滚界面；存储域仍是事实源，台账是可重建的派生审计轨迹。以 Host 级会话退出事件替代最后一个 agent 的启发式：暂缓（见包内 Dev Note）。
