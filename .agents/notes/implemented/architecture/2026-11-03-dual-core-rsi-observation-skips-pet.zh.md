# Agent Note: 观测驱动的循环跳过与像素勇者桌宠

Status: implemented

[English](2026-11-03-dual-core-rsi-observation-skips-pet.md) | 中文

## Problem

[后台自我进化的设计](2026-11-02-dual-core-rsi-background-evolution-panel.zh.md)在每个调度循环上都花费一个完整的蒸馏子代理，包括数学上注定徒劳的循环：一旦活跃策略与基准上限的差距小于阈值（分数以 1 为上界），任何候选都不可能过门；而与活跃策略内容完全相同的候选在确定性基准上必然打出相同分数。一项请求的演示还要求一个对守护核后台工作可见反应的桌面伙伴，把侧边栏的活动投影变成一个活着的界面。

## Decision

观测台（`tests/observation.spec.ts`）以脚本化的质量爬坡驱动调度守护核——后端故障、增量改进、回退、重复、饱和——并度量采纳结果、每轮墙钟时间、事件数与蒸馏器调用数。它的数据点名了上述两类徒劳循环，`runCycle` 现在让两者都不再做无用功：饱和跳过在摘要或蒸馏器运行前直接返回保留循环；内容去重跳过（结构化的 `artifactsEqual`）在基准评估前返回保留循环。两个跳过与普通保留结果共享同一条 `settleRetained` 记录路径。

桌宠是 `@deepseek-ai/dsh-experimental-client-ui-zelda-pet`：一个原创手绘像素勇者，渲染进插件同步插入的固定舞台，其姿态与气泡是对相邻活动视图的纯折叠（新修复→闪红，新进化→举心并给理由，循环运行→低鸣，否则行走；守护核停用则变灰）。它读取"自进化"面板挂载的同一 `dualCoreRsi` 命名空间——同一命名空间贡献的第二次 `$mount` 会被网关拒绝，因此勇者改为等待 `remote.dualCoreRsi`——并通过被认可的 `dsh.client.external` 导线层取得共享的 `createActivitySource`。连接重置分发随插件上下文急切注册，因为 React 的首次 store 订阅可能在挂载上下文退出很久之后才发生。

## Consequences

观测台钉死了优化的效果：爬坡携带 8 个值得蒸馏的步骤，断言只发生 7 次蒸馏器调用，重复循环与每个饱和后的循环一次都不花费；免费循环以约 0ms 结算，评估循环为 3–16ms，6 轮爬坡采纳 3 轮。对每个可晋升候选，跳过都保持行为不变——它们只短路门槛早已强制的结局。勇者成为活动 Remote 的第二个消费者，面板 e2e 现在端到端覆盖两者：在无 key 脚本蒸馏器下，侧边栏列出修复与进化，勇者闪红并打开面板，全程零用户输入。

## Alternatives considered

在调度器而非 `runCycle` 内跳过循环：被否决，因为饱和事实只有在 `ensureBenchmark` 解析出活跃分数后才持久，而它存在于循环内部。按间隔给蒸馏器调用设上限：被否决，因为预算掩盖原因；跳过移除的是可证明被浪费的工作，而不是给所有工作配给。桌宠挂载第二个 Remote 贡献：被否决，因为命名空间贡献是单挂载的；共享面板的挂载保持唯一导线所有者。操作系统级桌面覆盖窗口：暂缓；Web 舞台是本 harness 拥有的可交付界面，覆盖窗口会跨入桌面应用的窗口所有权。
